## Five questions

1. **Purpose and original intent.** §5 "consolidates all parameters that define a concrete instance of the strategy. They constitute the axes of analysis during implementation and backtesting" (`docs/DVT...md:967`), plus a parameter-interaction map (`:1066-1080`). §6 is a conditional escalation path: "If the base system (VAE with default configuration as described in Sections 4–5) underperforms ... apply iteratively in order of diagnostic priority" (`:1084-1086`), with Phase 0 as prerequisite (`:1088-1097`) and a terminal abandonment rule (`:1192`; `docs/strategy_philosophy.md:183`). §9 adds the modularity contract: risk model pure, return views removable (`strategy_philosophy.md:154-168`). So the unit's intent is threefold: **a reproducible instance**, **a pre-committed decision procedure**, and **separability of risk and return layers**.

2. **SOTA version.** (i) A single machine-readable parameter registry that *generates* the spec table and is hashed into every artifact (one immutable manifest per strategy instance), replacing four handwritten sources. (ii) A dimensionally coherent objective — either risk-budget tracking error `min Σ_k(c_k−b_k)²` (Roncalli 2013, ch. 7), or constrained `max H s.t. w'Σw ≤ V*` — so no weight is unit-dependent and no hidden normalization is needed. (iii) Hyperparameter selection inside the walk-forward training window (nested, as DVT §4.8 "Phase A" itself proposes, `:925`), not on the evaluation window. (iv) Multiplicity- and selection-aware inference: model confidence set (Hansen–Lunde–Nason 2011), White reality check, deflated Sharpe / PBO (Bailey et al.), t>3 conventions (Harvey–Liu–Zhu 2016) instead of a single uncorrected p<0.05. (v) Global sensitivity analysis (Morris/Sobol) over the joint parameter space rather than one-at-a-time narrative. (vi) Covariance-model evaluation by QLIKE/Diebold–Mariano rather than a variance ratio that is itself a tuning target.

3. **What prevents it, evidenced.** (a) Four parameter authorities with incompatible values: specs, `config.py`, notebook literals, and `notebook_helpers.assemble_full_config`; the saved run config is a fifth instance (§C-01). (b) An objective whose two terms are in different units (variance ~1e-4 daily vs entropy ~1–3 nats) and which is patched at runtime by an α rescaling and gradient clipping (`sca_solver.py:1100-1122`; `entropy.py:196-204`), destroying the documented ratio invariance (`DVT:771,788`). (c) Chains of runtime auto-adaptation: `K ← AU_max_stat ← EWMA half-life` (`pipeline.py:305-314`), `target_enb ← DGJ n_signal ← raw covariance` (`pipeline.py:2538-2545`), `r_max ← r` (`pipeline.py:338-353`). (d) Only one fold exists in the only real run (`results/diagnostic/report.txt:16` "Too few paired observations (1)"), so no trigger in §6 can be evaluated. (e) The roadmap's first four items are already implemented, so the "base system" it conditions on never existed.

4. **Real vs self-imposed constraints.** *Real*: 30 y daily history ⇒ ~7,560 time observations and `AU_max_stat≈85` at `r_min=2` (`DVT:1072`); estimation error dominating optimization (DeMiguel et al. 2009, cited by the doc itself `:1097`); 16 GB / stride-1 inference memory (`pipeline.py:1990-2001`); no defensible return forecast (hence μ=0 is honest); market beta is not diversifiable. *Self-imposed*: K=200 and its 1.5–2× "buffer" doctrine (`DVT:406-420`); T=504; `s_train=21`; simultaneous commitment to full-history Σ_z *and* EWMA 252; λ_risk=252 vs λ=1; the α grid; 3–5% hard caps and 30% turnover cap; the p<0.05-only kill test; using factor entropy as the *only* diversification metric; quarterly retraining vs per-rebalance refresh (`config.py:650`).

5. **What should be removed, merged, moved.** *Remove*: §5.1 as a normative table (it describes no runnable instance); the α-gradient normalizer and the entropy gradient clip (they compensate for a dimensional defect — fix the objective instead); the notebook's literal configs and `notebook_helpers` defaults (keep named profiles only); Iterations 1–4 from the contingency list (already defaults). *Merge*: `aggregation_method` + `aggregation_half_life` into one explicit parameter (the method enum admits only `"mean"` yet half-life silently makes it EWMA, `config.py:373-376`, `composite.py:155-165`); the two entropy layers into either factor-only (as specified) or a documented single objective; `target_enb`, α grid and n_signal into one declared model-selection rule. *Move*: Iteration 6 (PCA FRP) back to Phase 0 where it already serves as the null model and benchmark (`DVT:1095`); PC1-exclusion, market intercept, variance targeting and OOS refresh from implicit booleans into the documented model definition; hyperparameter selection from the in-sample frontier to nested validation. *No removal answer*: the unit's veto principle (complexity must earn its place) is the one thing worth preserving verbatim.

## Root-cause hypotheses

**RC1 — Four-source parameterization with no provenance (drives C-01, M-10, M-15, MIN-17, MIN-19).**
The instance is defined simultaneously by `config.py` dataclass defaults, notebook literals, `assemble_full_config` overrides, and prose in DVT/ISD. Nothing reconciles them, and artifacts record only the *effective* JSON without a spec reference (`results/config.json` records no data source; `results/diagnostic/config.json` says `data_source: synthetic` for a Tiingo run). Consequences: every "baseline" in the documents is a fourth, unrun configuration; no result is attributable to a documented instance; the roadmap cannot reference a starting state. *Structural alternatives*: (a) one declarative manifest (YAML/TOML) that generates both the config object and the spec table, with the manifest hash written into every artifact and a CI check that fails on drift — cheap, high leverage, but does not stop semantic drift inside code; (b) spec-first code generation, notebooks limited to named profiles — maximal coherence, slower experimentation; (c) treat the configuration as an experimental factor with explicit manifest ids and a results database — best auditability, but only works if (a) or (b) already exists.

**RC2 — A dimensionally incoherent objective patched by hidden normalizers (drives C-02, C-03, C-06, M-12).**
`−λw'Σw + αH` mixes daily variance (~1e-4) with nats (~1–3). Rather than non-dimensionalizing, the code rescales α at equal weights and clips the entropy gradient; the notebook concedes the "700:1" dominance. Then, because a plain entropy target over 26 factors is economically unattractive, a tilted budget and a 20% idiosyncratic layer are added, and because the resulting ENB is inflated, the selection rule had to be switched to factor-only entropy (comment at `frontier.py:391-397`). Each patch is locally reasonable and jointly destroys the meaning of α, H, ENB, and the "operating point". *Alternatives*: (a) risk-budget tracking error `min Σ_k(c_k−b_k)²` — removes α entirely, makes the budget explicit, scales naturally, but abandons the "risk minimization primary" narrative and requires defending b; (b) constrained `max H s.t. w'Σw ≤ V*` with `V*` from a benchmark — one interpretable knob, comparable across models, but V* is itself a tuning choice and risks collapsing to min-variance; (c) keep the penalized form but divide the risk term by a reference variance and H by ln(AU) — minimal change, restores invariance, but the reference portfolio introduces a new arbitrary choice and still needs a budget policy for the entropy target.

**RC3 — Adaptation substituted for specification, with circular dependencies (drives C-05, M-08, M-09, M-10, M-12).**
Derived quantities are computed from other estimated quantities and then presented as parameters: `K ← 2·AU_max_stat ← EWMA half-life`; `target_enb ← DGJ n_signal on raw covariance ← EWMA`; `r_max ← r`; `alpha_eff ← Σ at equal weights`; noise eigenvalues kept in `Sigma_assets` but dropped from entropy. The run's K=52 and α=0.001 are outputs of this chain, not choices. The doc's "resolved" labels (`DVT:998,1000,1002,1060`) hide that several "resolved" values are not even the code's values. *Alternatives*: (a) freeze every derived quantity in the run manifest and treat it as an audited output, with a pure-input config; (b) delete auto-relaxation and fail loudly when capacity/statistical constraints bind, forcing an explicit universe/K decision; (c) replace the adaptation chain with a small pre-registered factorial design of complete configurations, so adaptation becomes an experimental factor. Trade-offs: (a) preserves current behavior and makes it diagnosable, but leaves the circular reasoning intact; (b) is scientifically cleanest, but will make many universes unrunnable — which is informative; (c) is the only option that yields estimable effects, at the cost of many more runs.

**RC4 — Decision procedure written after the decisions (drives M-07, M-13, MIN-18, MIN-19, and the response to C-06).**
§6 reads as a pre-commitment device but functions as a menu. Phase 0's criterion is "beat four benchmarks"; the terminal rule is "beat PCA, p<0.05"; the harness cannot compute the test; and the first four alternatives are already defaults. The one number the run does provide — VAE loses to 1/N, inverse-vol and ERC — is the exact condition §6.1 says invalidates the complexity, and it produced no decision. *Alternatives*: (a) freeze instances V0..Vn as manifests, evaluate all on identical folds, and decide by a model confidence set with a pre-registered α (and a deflated-Sharpe/PBO adjustment for the number of instances tried); (b) ablation-first from PCA FRP as the null, adding one mechanism per instance with a fixed evaluation budget; (c) replace the roadmap genre with a model-risk dashboard whose thresholds (covariance QLIKE, EP, ENB stability, turnover) gate promotion — operationally natural, but thresholds become the new unfalsifiable parameters unless set before seeing results.

**RC5 — "Memory" as slogan, implemented as two contradictory smoothing choices (drives C-04, M-09, M-14, HYP-21).**
The philosophy mandates permanent crisis memory; the code applies a 60-day half-life to `B_A`, a 252-day EWMA to Σ_z, and refreshes the risk model every rebalance. Each choice is individually defensible as responsiveness; together they make the anti-cyclical premise false. The repo even contains the correct analysis (`sigma_z_ewma_justification.md`), which the run overrides without a trigger. *Alternatives*: (a) declare a single memory policy (full history) and enforce it in code, with EWMA variants only as named instances; (b) declare a single *response-speed* parameter shared by aggregation and Σ_z, so "memory" is one number with one meaning; (c) abandon the memory claim and position the strategy as regime-adaptive, measuring the adaptation explicitly (covariance forecast loss by horizon). Trade-off: (a) is testable and matches the documents but may underperform in regime shifts; (c) is honest but removes a core selling point; (b) is elegant but conflates two different estimation problems (exposure shape vs factor covariance).

## Verdict

As a control system for a research program, U15 fails. Its inventory describes an instance that has never run (C-01), its objective is not the one in the specs (C-02/C-03), its memory principle is inverted in the only real run (C-04/M-09), and its two quantitative guards are vacuous (C-05 auto-relaxation; C-06 selection at the lowest α with three incompatible ENB definitions). The roadmap is thoughtful prose but is not a contingency plan: the first four alternatives are already defaults, the abandonment criterion is weaker than the one in the same section's prerequisite and cannot be computed with the available folds, and the evidence that already exists (VAE below 1/N, inverse-vol and ERC) is the very evidence the document says should end the program. The parts worth keeping are the veto principle, the Phase 0 benchmark idea, and the modularity *intent* — all three are undermined by the parameter layer they are embedded in. This unit needs to be rebuilt around one immutable manifest, one dimensionally coherent objective, one explicit memory policy, and one pre-registered comparison; patching values would leave every root cause in place.

Score: 2/10
