## Five questions

**1. Purpose and original intent (spec).**
The intent is explicit and correct: "la complexité du VAE n'est justifiée que si elle produit un bénéfice OOS mesurable et statistiquement significatif par rapport à des alternatives plus simples, sur les mêmes données, avec les mêmes contraintes, évaluées par les mêmes métriques" (`docs/Benchmark_latent_risk_factor.md:5`), and "Toute divergence invalide la comparaison" (`:11`). Six benchmarks are designed to be an ablation ladder, "ordonnés par complexité croissante. Chacun isole une composante spécifique" (`:71-72`), summarized in the models × components matrix (`:313-324`). The unit is therefore not a horse race but an attribution device: it must say *which* VAE component (correlation estimation, factor decomposition, factor-space diversification, nonlinearity, feature enrichment) earns its cost.

**2. State of the art for this objective.**
A SOTA version is a *parity-controlled nested ablation*: identical universe, folds, rebalancing, costs, risk-model post-processing and metrics; only the exposure estimator changes between rungs. The literature supports each rung as chosen: 1/N (DeMiguel, Garlappi & Uppal 2009), Ledoit-Wolf shrinkage (2004; nonlinear 2020 is named as a sensitivity, `:95`), ERC via Spinu (2013), PCA with Bai-Ng IC₂ (2002). What is missing versus SOTA is (i) RMT cleaning of the linear factor model (Laloux et al. 1999; Bun, Bouchaud & Potters 2017) — the current PCA rung has no shrinkage at all while the VAE does (`src/benchmarks/pca_factor_rp.py:85`); (ii) the control that actually separates "neural" from "nonlinear": an untrained/random-encoder VAE and a *linear* autoencoder on the same 504-day windows, plus kernel PCA; (iii) external factor models as a floor (Fama-French; IPCA, Kelly-Pruitt-Su 2019; ML asset pricing, Gu-Kelly-Xiu 2020); (iv) a model-confidence-set test (Hansen-Lunde-Nason 2011) rather than only pairwise Wilcoxon; (v) net-of-cost comparison. The doc itself concedes that the PCA rung bundles several differences ("auto-pruning vs IC₂, K ≈ 80 facteurs vs k ≈ 10, non-linéarités vs linéarité", `:146`), which is honest but means one rung cannot identify one cause.

**3. What prevents it, and which obstacles are only apparent.**
Evidenced blockers: different universes (VAE 639 stocks vs benchmarks 477 — `results/diagnostic/diagnostic_report.md:48` vs `results/diagnostic/strategy_comparison.csv:3`); different OOS return processes (VAE quarterly rebalancing with drift, benchmarks one fit and constant-weight evaluation — `src/integration/pipeline.py:2718-2766`, `:2979-2996`); primary metric H absent for every benchmark (`src/benchmarks/base.py:154-199`; `results/diagnostic/diagnostic_report.md:119`); ERC numerically identical to 1/N (`strategy_comparison.csv:3,6`); PCA risk model without the VAE's shrinkage/variance targeting (`pca_factor_rp.py:85` vs `src/risk_model/covariance.py:192-353`); only one real OOS fold (`results/diagnostic/report.txt:10-16`).
Only apparent: "benchmarks cannot be scored on entropy" — `compute_entropy_only` already exists and is imported by the PCA optimizer (`pca_factor_rp.py:20-21`); "fairness requires a separate benchmark runner" — the pipeline already has a benchmark loop (`pipeline.py:718-724`) and a tested benchmark rebalancing simulator (`oos_rebalancing.py:965`); "constraint parity is hard" — `tests/unit/test_invariants.py:849-909` already verifies it; "benchmarks need different solvers" — all factor rungs already share `compute_variance_entropy_frontier`. The gap is wiring, not missing theory.

**4. Real constraints vs self-imposed choices.**
Real: Tiingo data quality (35.31% missing, `diagnostic_report.md:30`), no CRSP/delisting returns, compute cost of 34 VAE folds, illiquidity/costs. Self-imposed: buy-and-hold benchmarks while the VAE rebalances quarterly (`notebooks/dashboard.ipynb:345`, `config.py:618`); constant-weight benchmark returns instead of the doc's passive drift (`:65`); no H/crisis metric for benchmarks; no shrinkage/VT in the PCA rung; silent fallback to 1/N; a second, differently-configured benchmark engine (`run_benchmarks.py:190,218-229`); single-fold real-data diagnostic; S&P 500 in the same constrained comparison.

**5. What to remove, merge or move.**
- **Remove** the separate `run_benchmarks.py` comparison path (keep it only as a debug CLI), the silent 1/N fallbacks from the decision data path, the per-model `evaluate()` implementations, and the S&P 500 row from constrained-strategy tests.
- **Merge** universe construction (one NaN rule for VAE and benchmarks), OOS simulation (one rebalancing/drift/delisting/cost function), metric computation (one shared function producing H, crisis return, var ratio for every model that has a Σ), and the risk-model post-processing (shrinkage, VT, signal split) behind one `FactorRiskModel` builder in which only the exposure estimator differs.
- **Move** the PCA rung to be exactly "VAE replaced by PCA, everything else identical"; move the decision layer to consume a tidy all-models × all-metrics frame so a missing primary metric is an error, not a skipped test.
- This deletes nothing that carries a strength: the ablation ladder, common ABC, shared constraints, and correct per-benchmark mathematics all survive.

## Core strengths to preserve
- **The ablation ladder and its component→benchmark map** (`docs/Benchmark_latent_risk_factor.md:71-72,313-324`). This is the intellectual core of the unit: it converts a model-selection question into a set of falsifiable component claims. Any redesign must keep exactly this mapping.
- **The PCA+vol control** (`:148-158`; `pca_vol.py`). It anticipates the most plausible alternative explanation of a VAE win — richer inputs — and includes the control. Keep it and extend the idea to the other confounds.
- **One shared abstract interface and one shared constraint contract** (`ISD:1996-2026`; `base.py`; `test_invariants.py:849-909`). Keeps every comparison on the same contract and already has enforcement tests.
- **Correct, non-trivial mathematics**: PCA scaling algebra (`pca_factor_rp.py:78-108`), Bai-Ng IC₂ (`:112-142`), Spinu ERC with the c=1 insight and solver fallbacks (`erc.py:1-17,84-190`), min-variance QP with turnover inside the convex set (`min_variance.py:68-78`), PCA-vol unit rescaling (`pca_vol.py:110-133`). Do not "simplify" these away.
- **Identical metric arithmetic for the buy-hold path** (`base.py:171-198` vs `metrics.py:629-662`). One implementation of return/vol/Sharpe/MDD is what makes the comparison interpretable at all.
- **Shared fold schedule and expanding windows** (`folds.py:57`; `pipeline.py:604-606`; `run_benchmarks.py:203-211`), with no look-ahead in the benchmark fit (`pipeline.py:2937,2976`).
- **No per-benchmark tuning of penalties** (`docs:48`; `pipeline.py:2954-2969`) and **deterministic, VAE-independent benchmark outputs**. This makes the benchmark numbers a stable control across VAE seeds — a property worth keeping and exploiting.
- **The pre-registered decision matrix** (`docs:289-309`) and the honest statistical layer (`reporting.py:46-114`; Wilcoxon/bootstrap/Holm). The decision rule is good; what is missing is a comparison powerful enough to feed it.
- **The unused-but-tested benchmark rebalancing simulator** (`oos_rebalancing.py:965`; `tests/unit/test_oos_rebalancing.py:570-860`). It is the fastest route to protocol parity: wire it in rather than build anything new.

## Verdict
The *theory* of U13 is sound and, in places, excellent: it builds a literature-grounded, one-component-at-a-time ablation ladder, implements the linear factor model and ERC with correct and non-obvious mathematics, enforces a common interface and constraint contract, shares fold dates and metric formulas, and pre-registers a decision rule. The failure is not conceptual but architectural execution: the VAE and the benchmarks are run as two different experiments — different universes (639 vs 477), different OOS processes (quarterly rebalancing with drift vs one-shot constant weights), missing primary metrics (no H_norm or crisis return for any benchmark), a PCA rung without the VAE's shrinkage/variance targeting, a dead turnover constraint, and a silent ERC=1/N fallback — on a single real OOS fold that cannot support the paired-test protocol. Consequently the comparison cannot currently attribute performance to any VAE component, and the "Scenario C" recommendation is not evidenced. The encouraging fact is that the missing pieces already exist in the repository (`simulate_benchmark_oos_rebalancing`, `compute_entropy_only`, shared constraint tests, the pipeline benchmark loop); the redesign is primarily deletion and rewiring to a single comparison path, not new modeling.

Score: 6/10
