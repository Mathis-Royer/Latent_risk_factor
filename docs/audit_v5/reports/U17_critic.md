## Five questions

**1. Purpose and original intent.** §00 is the anti-drift layer for a 16-module, multi-agent build: conventions CONV-01..10 (`docs/ISD:41-54`), invariants INV-001..012 with detection tests (`:56-174`), a mandatory decision log (`:176-211`), a symbol glossary (`:213-231`), and "Inter-Module Interface Assertions" as executables (`:433-536`). The declared machine-readable contract is `docs/assertions/contracts.yaml` (`:347-348`) — **it does not exist**. Intent was one theory, implementable in parallel without cross-talk (`:191-196`). Measured against that intent, the unit failed at the artifact level before any modelling issue arose.

**2. State of the art for this unit.** Executable specification and conformance testing: contracts (Meyer, *Object-Oriented Software Construction*, 1997), property-based testing (Claessen & Hughes, ICFP 2000), metamorphic testing for pipelines where no oracle exists. Experiment provenance and configuration-as-artifact (Sculley et al., "Hidden Technical Debt in ML Systems", NeurIPS 2015; Mitchell et al., "Model Cards", 2019), architecture decision records with explicit supersession (Nygard, 2011). For the statistics: proper scoring/calibration (Gneiting & Raftery, 2007) and multiple-testing-aware evaluation (Bailey & López de Prado, "The Deflated Sharpe Ratio", 2014). A state-of-the-art U17 would consist of: one normative ID space (CONV/INV/ADR), machine-checked at CI against the production code path; every results artifact embedding data hash, git SHA, config hash, checkpoint hash and spec tag; and invariants expressed as *metamorphic* statements (permute factor labels → identical weights; scale all returns by c → identical weights; permute stock order → identical weights), not as assertions about helper functions with fabricated inputs.

**3. What prevents it, evidenced.** (a) Four competing registries with no ownership: DVT, ISD, `divergences.md`, `implementation_decisions.md` (`docs/implementation_decisions.md:381-385` says "*(none identified)*" while `docs/divergences.md` lists 10). (b) The test suite elevates a deviation log above the specs: `tests/unit/test_divergences.py:5-7` — "(code + divergences.md), NOT the raw DVT/ISD formula when they differ". (c) The invariants are tested on code paths production never takes (`tests/unit/test_invariants.py:616` calls `compute_entropy_and_gradient` without `D_eps`, while `src/portfolio/sca_solver.py:912-915` always passes it). (d) Numeric operating point lives in the notebook; `src/config.py` is a suggestion (`results/diagnostic/config.json` overrides K, dropout, lr, batch, patience, r_max, w_max, φ, n_starts, idio weight). (e) The audit documents were never recomputed: `docs/assertions/cross_reference_report.md:400` states `(-1+sqrt(15121))/2 = 86.98 → 86`; the expression equals 60.98.

**4. Real constraints vs self-imposed.** Real: 7,874 trading days and 639-788 names (`results/diagnostic/diagnostic_report.md:26-28`) bound how many latent factors are estimable; the 21-day embargo (`src/walk_forward/folds.py:65-69`) is a genuine no-look-ahead device; 16 GB RAM makes 34 folds × 32 HP configs (`docs/implementation_decisions.md:186`) and 500-epoch training mutually exclusive; vendor data lacks delisting returns. Self-imposed: the DVT/ISD two-document structure; the rule that "ISD primes DVT" by fiat (`docs/divergences.md:23`); treating a coverage inventory as a conformance gate; accepting three different factor counts; two entropy layers; per-fold α search over 12 values; reporting a pretrained, one-fold diagnostic as a walk-forward; restoring the risk-model scale silently instead of reporting it.

**5. What should be removed, merged or moved.** *Remove*: the separate `divergences.md` registry and the "Divergences: none identified" section; the invariant tests that assert helper behaviour with synthetic inputs; the hidden `_variance_targeting_scale()` stage (report miscalibration as a result, do not repair it); the seventh benchmark (`sp500_index`) or its omission from the spec; the pretrained-checkpoint reporting path. *Merge*: DVT+ISD into one normative document with one ID space; `divergences.md` into `implementation_decisions.md` as ADRs with `supersedes` links; the three factor counts into one canonical `AU_eff = n_signal`. *Move*: the operating point from `notebooks/dashboard.ipynb` into a versioned config recorded in every artifact; α selection from per-fold in-sample elbow search to a pre-registered global rule; provenance emission into the report writer, not the notebook. Nothing new is required — the missing `contracts.yaml` is a *removal* of the prose registry in favour of generated content.

## Root-cause hypotheses

**RC1 — Specification is prose with no owner and no executable enforcement.**
Four registries, three conflicting authority rules (`docs/divergences.md:23`; `tests/unit/test_divergences.py:5-7`; `docs/implementation_decisions.md:385`), and a declared contract file that does not exist (`docs/ISD:347-348`). Explains CRI-01, MAJ-05, MAJ-06, MAJ-07, MIN-12, A1/A2/A10 — including why a DVT typo could survive in three documents: no machine checks any number. Structural alternatives: (a) *single source of truth* — one normative document + generated appendix from `src/config.py` and a real `contracts.yaml`; prose demoted to commentary; (b) *intent-ID provenance* — every result artifact must cite an intent ID and every intent ID must resolve to a spec paragraph and a test; CI fails on dangling IDs; (c) *spec tagging* — freeze spec versions and label every artifact with the tag; the audit then compares like with like instead of comparing a 2026-02 spec to 2026-11 code.

**RC2 — The pipeline repairs its own failures silently instead of reporting them.**
`_adapt_vae_params` (K 75→52), per-factor variance targeting, idio variance targeting, `B_A` clipping, DGJ truncation AU 26→12, `_compute_alpha_eff` gradient renormalisation. Each is locally defensible; jointly they absorb model error into constants, so no backtest can attribute performance to the VAE. Explains CRI-03, MAJ-08, MAJ-10, HYP-01 and *why the variance ratio is still 2.742 after calibration*. Structural alternatives: (a) *report-don't-repair* — no rescaling between risk model and optimizer; publish the miscalibration as a diagnostic and let performance reflect it; (b) *staged risk model with ablation* — each calibration is a named, versioned stage with recorded inputs/outputs, and results are reported with/without each stage; (c) *replace the ad-hoc repair with one principled estimator* (EWMA/shrinkage on z_hat with a single, estimated scale), eliminating the per-factor and per-block fudges.

**RC3 — Verification is aimed at the code, not at the theory (and the verifier is not verified).**
Tests assert constants the implementation produced (`docs/assertions/cross_reference_report.md:20` — the test "verifies DVT §4.8 table values using the **code** formula"); INV-007/INV-009 test a branch production never executes; the divergence audit's arithmetic is wrong in all three places it appears. Explains CRI-01, MAJ-05, MAJ-07, MIN-12. Structural alternatives: (a) *metamorphic invariants on the production path* — label/order/scale permutation tests through the real `run_walk_forward` plumbing; (b) *N-version verification* — an independent, deliberately slow reference implementation of entropy/gradient/ERC/AU used only in tests, so agreement is evidence rather than tautology; (c) *pre-registration* — write expected numbers before running, then a script that diffs documents against code and fails on drift.

**RC4 — The theory has more free parameters than the data can identify.**
Three factor counts, two entropy layers, an idio weight, a budget tilt, per-factor VT, α renormalisation, λ=252, φ=0, cardinality method, dropout, K, T — against ~7.9k days and one fold. Every knob can absorb an error, so no conclusion is identifiable. Explains CRI-03, CRI-04, MAJ-08, MAJ-09, MAJ-10. Structural alternatives: (a) *pre-commit* — fix every second-order knob from literature, report sensitivity for at most two; (b) *collapse to one estimated object* — one factor count, one objective layer, no VT, accepting worse in-sample fit for interpretability; (c) *hierarchical/empirical-Bayes nuisance scales* — VT as a single hyperprior with a reported posterior, not a per-factor multiplicative constant, and factor count selected by a criterion fixed before seeing the OOS.

## Verdict

The ISD §00 is the best-constructed document in this repository and the wrong kind of object: a prose constitution for a system whose real constitution is `src/config.py` plus a notebook. Its conventions are largely honoured in spirit, but every load-bearing quantity has drifted: the number of factors (K→AU→n_signal), the objective (single-layer→two-layer), the α calibration (elbow→gradient-normalised, per-fold), the risk-model scale (model→holdout re-estimation), and the benchmark constraints (optimisation→clip-and-renormalise). None of these drifts is fatal individually; collectively they mean the phrase "the strategy" in the audit brief does not refer to a unique object, and no results artifact identifies which object it measured. Worse, the layer built to detect drift — `divergences.md`, `cross_reference_report.md` — is itself drifted and arithmetically wrong in every computation I checked, and the test suite explicitly declares the drift log superior to the specification, which makes the specification unfalsifiable. The strongest steelman is that silent adaptation is *how research code survives*: `_adapt_vae_params` lets the pipeline run at K=52 on 788 names, and variance targeting prevents a mis-scaled Σ from paralysing the optimiser. That is true and it is exactly the problem: those adaptations are where the science happened, and they were never documented, tested, ablated, or reported. A coherent redesign should not add a contracts file; it should *delete* the prose registry, make the config the spec, force every repair stage to be visible in the results, and reduce the factor-count question to one answer. As a coherence unit, this is a well-intentioned constitution that the code has already seceded from.

Score: 3/10
