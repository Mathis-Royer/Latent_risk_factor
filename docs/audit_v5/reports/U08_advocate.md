## Five questions

**1. Purpose and original intent.** §4.6 exists to convert a *window-level* encoder into *asset-level* inputs for a cross-sectional risk model: each stock's windows are encoded (no sampling), the local latent vectors are pooled into a "composite risk profile" `μ̄_i`, and the stacked profiles form `B` (`docs/DVT_...v4_1.md:644-646, 660-672`). Three explicit design decisions: stride 1 to remove a calendar degree of freedom (`:648-650`), uniform mean as the default aggregator "preserving memory of all historical regimes" (`:656`), and B as **shape-only** exposures that must be rescaled by trailing volatility downstream (`:672`). §4.6/§4.7 then add the **AU filter**: `A = {k : KL_k > 0.01 nats}`, motivated purely by conditioning of `B_A^T B_A` when `rank(B) ≈ AU ≪ K` (`:712-720`). MOD-006 restates this as three sub-tasks plus invariants INV-003 (`B_A.shape == (n, AU)`, `AU ≤ AU_max_stat`), CONV-07 (AU measured once per retraining), INV-005 (inference uses only training windows) (`docs/ISD...md:1592-1663`).

**2. What a state-of-the-art version would look like.** Four upgrades, none of which requires abandoning the current design:
- *Aggregation by conditioning, not pooling.* The modern way to get per-stock exposures from a deep model is a conditional exposure function `β_{i,t} = g(state_i,t; θ)` — the conditional autoencoder of Gu, Kelly & Xiu (2021, *J. Econometrics*) and IPCA (Kelly, Pruitt & Su 2019, *JFE*). The uniform mean over window codes is the `g = mean` special case with no state dependence. Industrial risk models (Barra/Axioma) sit in between: exposures from time-series regression with EWMA weights of roughly 90–180 days.
- *Factor count from the recovered factor returns, not from a KL heuristic.* Onatski (2010) and Bai & Ng (2002) applied to `{ẑ_t}` (the `AU`-dimensional factor returns the model already produces) is the statistically correct place to test the number of factors; the current code applies Bai-Ng to the **raw return panel** (`pipeline.py:2042-2047`).
- *Use the encoder's own uncertainty.* `log_var` is computed for every window and then discarded except for the KL sum (`composite.py:88`, which returns `mu` only). A SOTA version weights each window by its posterior precision, which is precisely the "confidence weight" the spec wishes for but never implements (`DVT:674`).
- *Active-unit definition as in Burda et al. (2016)* — the covariance of the per-sample KL with the data, not its mean (see ADV-17).

**3. What prevents it — and which obstacles are only apparent.**
- *Apparent:* "stride-1 is needed for statistical accuracy." It is not; the spec's own ESS argument (`DVT:651`, `N_eff ≈ T_hist/T ≈ 15`) says mean aggregation is quasi-invariant to stride ≤ 21. The only real cost of stride-1 is memory — and that is an implementation artifact (materialising `N×T×F`), acknowledged in code (`pipeline.py:1998-2001`, "~32GB for stride=1") while the spec budgets only the 5.6 GB of `μ` (`DVT:648`).
- *Apparent:* "AU = 26 is a property of the data." In the shipped configuration it is a property of `sigma_z_ewma_half_life = 252` (`results/diagnostic/config.json`), which drives `N_eff ≈ 727` and `AU_max_stat = 26` (`active_units.py:114-117`). The data itself says 47 dimensions exceed 0.01 nats (`diagnostic_data.json:38-63`). So the "discovered" factor count is set by a covariance-estimator hyperparameter, not by the KL spectrum.
- *Real:* the encoder has no cross-window state, so a *time-indexed* exposure is impossible without retraining; the mean is the only aggregation the architecture admits.
- *Real:* window counts per stock differ by up to 20× (35% missing data, 788 stocks, `diagnostic_report.md:20-22`), so B rows are estimated with very different precision and nothing down-weights them.

**4. Real vs self-imposed constraints.** *Real:* effective time-series length for Σ_z; cross-sectional identification (`AU < n`, correctly enforced at `pipeline.py:2022-2028`); listing history; missing data. *Self-imposed:* stride-1 materialisation (memory only); half-life expressed in windows rather than days; AU defined solely by mean KL; posterior variance discarded; two independent AU-capping mechanisms; B normalisation/clipping placed in the integration layer rather than in inference.

**5. What to remove, merge or move.**
- **Remove the stride-1 materialisation** (stream windows per stock, or revert to stride 21). Nothing statistical is lost for a mean aggregator; the spec's own ESS argument is the justification for deleting it.
- **Remove `measure_active_units`** (`active_units.py:19-89`) — it is production-dead, the pipeline re-derives AU inline, and all MOD-006-required tests point at the dead copy.
- **Merge** `truncate_active_dims` (`:140-163`) and `post_filter_au_bai_ng` (`:166-203`) into one bound parameterised by the estimator actually in use; today they are two sequential caps with different semantics.
- **Remove the "half-life in windows" parameter** until it is expressed in days; with `half_life=0` the elaborated strength (full-history memory) is untouched and the ordering defect (ADV-14) becomes inert.
- **Move** per-factor z-scoring (`pipeline.py:2093-2098`) into `aggregate_profiles`, so the exposure matrix has a defined output convention; **remove** the scalar `B_A *= (1-alpha)` shrink (`:2112-2117`), which shrinks *variance*, not covariance.
- **Do not remove:** encode-only determinism, KL fused into the same pass, the AU filter itself, the parameter-count guard (recalibrate, don't delete), training-window-only inference.

## Core strengths to preserve
1. **Determinism by construction** — `eval()` + `no_grad()` + `encode()` returning `mu`, with the KL branch reading the same `mu` from the same encoder call (`composite.py:62-89`, `model.py:152-167`). Any redesign that reintroduces sampling in the exposure path breaks the meaning of B.
2. **Training-window-only inference, B fixed between retrainings** (`pipeline.py:1976-1980`, `DVT:676`). This is the unit's anti-look-ahead guarantee and must survive any re-architecture.
3. **Fused AU measurement in the exposure pass** (`composite.py:78-86`, `pipeline.py:2010-2016`): one model state, one window set, one number. Do not split AU into a separate stage or a separate forward pass.
4. **The parameter-count guard itself** (`AU_max_stat`) and its **Kish `N_eff` coupling to the Σ_z estimator** (`active_units.py:100-137`). The numbers are right and the coupling is right; only the doc formula and the `r_min` rationale need to follow the estimator. Deleting the guard because it binds would trade an explicit trade-off for an implicit one.
5. **AU filtering instead of ridge/SVD truncation** (`DVT:712-720`): the only route that consumes the auto-pruning signal rather than re-discovering it with a new hyperparameter.
6. **Shape-only exposures with volatility restored downstream** (`DVT:672,724-744`, `windowing.py:255-260`): the separation of shape (from the encoder) and scale (from trailing vol) is analytically clean and is what makes the date-specific rescaling argument work.
7. **Static-exposure comparability with the PCA benchmark** (`pca_factor_rp.py:68-80`): the VAE-vs-PCA comparison is fair precisely because both use full-sample, static exposure matrices. Any move to time-varying VAE exposures must be mirrored on the PCA side or the benchmark stops bounding the contribution of the VAE.

## Verdict
The mathematics of this unit is correct and its central design decisions are defensible. Deterministic encoding, the KL definition, the parameter-count bound, and the Kish effective-sample coupling are all right — in two cases (ADV-04, ADV-05) the code is *more* correct than the document that specifies it. The AU filter is well motivated and empirically matches a genuinely bimodal KL spectrum. The weaknesses are not conceptual but structural: the aggregation layer carries a unit mismatch (half-life in windows while stride is 1 day), an ordering violation that silently converts EWMA into random subsampling, a dead production path with its tests pointed at the wrong function, and a truncation rule whose justification (Ledoit-Wolf parameter counting) no longer matches the estimator it protects (a DGJ spiked shrinker on EWMA covariances) — which in the only real run cost 21 informative dimensions. None of these requires new mathematics; several require *deleting* machinery: stride-1 materialisation, `measure_active_units`, the second AU cap, the window-indexed half-life, and the scalar exposure shrink. What must be preserved is the determinism, the training-only inference, the fused measurement, the AU filter and the parameter-count guard — recalibrated, not removed.
