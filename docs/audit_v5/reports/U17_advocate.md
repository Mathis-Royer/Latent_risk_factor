## Five questions

1. **Purpose and original intent.** The ISD is explicitly the "Operational Instantiation" of the DVT (ISD:3–7), compiled under ISD Methodology v1.0, whose Part B.6 defines inter-module assertions as "the **primary mechanism for detecting inconsistency** when modules are implemented by different agents" (ISD_methodology.md:521–525) and requires each assertion to reference the invariant it verifies (ISD_methodology.md:580). U17's intent is therefore not literary coherence but **composability**: fixed cross-module conventions (ISD:41–54), twelve mathematical/inter-module invariants with violation and detection clauses (ISD:56–174), and a mandatory decision log for spec gaps (ISD:176–211). The unit is the constitution that lets sixteen modules and multiple agents form one theory.

2. **What a state-of-the-art version would look like.** Design-by-contract (Meyer, 1992) with executable pre/post-conditions at every module boundary; a single machine-readable contract artifact (the planned `contracts.yaml`, ISD:348) from which prose and tests are generated; requirements traceability under ISO/IEC/IEEE 29148 with bidirectional spec-ID ↔ test-node mapping; Architecture Decision Records (Nygard, 2011) with immutable statuses; and run provenance (resolved config + code commit + data manifest/hash) as in MLflow-style experiment tracking or "model cards" (Mitchell et al., 2019). The finance-specific additions are pre-registered evaluation rules and point-in-time data manifests. The repo already has fragments of all of these; the state of the art is that they are **derived from one source and CI fails on drift**, not hand-maintained.

3. **What prevents it from reaching that.** Four seams, all documented-vs-document rather than mathematical: (i) manual transcription of the same constants across DVT, ISD, config, notebook and code produces four-way drift (K = 200 at ISD:220 vs 50 at config.py:179 vs 100 at notebook:554; λ_co_max = 0.5 at ISD:1392 vs 0.1 at config.py:237 vs 0.5 in the diagnostic run); (ii) no declared DVT↔ISD precedence — the rule appears only inside a divergence memo (divergences.md:23); (iii) the divergence register is not exhaustive and not regenerated when code changes; (iv) the only real-data run uses a different risk model than the ISD specifies (see U17-ADV-08, -14). **Which obstacles are only apparent:** the mathematics is not incoherent. On the five consequential identities I checked (D-factor, scalar σ², dual rescaling, principal-basis entropy gradient, validation ELBO), DVT and ISD agree and the code implements them exactly (U17-ADV-01, -02, -03, -21). The "the theory is inconsistent" impression is produced by the bibliographic layer, not the theory.

4. **Real vs self-imposed constraints.** Real: the data substitution CRSP→EODHD→Tiingo (DVT:291, ISD:20, README:31) because CRSP is unavailable; the absence of delisting returns in Tiingo (scripts/download_tiingo.py:911), which makes the ISD's Shumway imputation inert (ISD:604–605, 736–737); profile-dependent K/epochs forced by compute; parallel agents editing shared documents. Self-imposed: hardcoding `T == 504` in a normative assertion (ISD:441) although the config accepts T ≥ 63 (config.py:190); duplicating parameter tables in four places; maintaining two overlapping registers; describing λ_co without its scaling convention and then multiplying it by D/2 in code (U17-ADV-06); leaving a phantom `docs/isd/00_global.md` and `contracts.yaml` in the artifact map (ISD:341–348, 2634).

5. **What should be removed, merged or moved.** Remove the hand-maintained `docs/assertions/cross_reference_report.md`; replace it with a generated INV/CONV → pytest-node matrix (or delete it — the executable tests already are the contract). Merge `divergences.md` into `implementation_decisions.md` under one schema and delete "Divergences: (none identified)" (implementation_decisions.md:385). Move all parameter **values** out of DVT/ISD prose into a single resolved-config schema; docs should cite parameter names and domains, not literals. Remove the ISD's pseudo-code interface assertions and "Required Tests" name lists; keep the properties and point to `tests/unit/test_interface_contracts.py`. Remove the phantom artifact map from ISD/CLAUDE.md or create the files. Move the post-ISD architecture (market intercept, PC1 exclusion, per-factor variance targeting, spiked shrinkage, WLS, two-layer entropy) into one current model card that supersedes MOD-007/008, instead of leaving it split between code comments and justification memos. Nothing in this list removes a strength: the invariants, runtime asserts and tests survive intact.

## Core strengths to preserve

1. **The invariant triple.** Every INV states the property, the violation mode and a detection/test (ISD:56–174). This is the right abstraction level: it turns theory into falsifiable engineering. Any redesign must keep a numbered invariant list with the same three fields.
2. **Runtime enforcement with ID tags.** INV-001/002/006 are asserted in production code (loss.py:343, 346–348, 399), and tests cite the same IDs. This bidirectional link is the single most valuable asset in the repository.
3. **CONV-01..10 as cross-module conventions**, each tested in a dedicated suite. These are the interface semantics (log returns, per-window z-scoring, tensor layout, scalar σ², AU threshold, dual rescaling, expanding window, point-in-time) that make independently built modules composable.
4. **Executable interface contracts.** `tests/unit/test_interface_contracts.py` (959 lines) is a faithful, stronger version of ISD §"Inter-Module Interface Assertions", with exact numeric checks at each boundary. Preserve the tests; the prose duplicate can go.
5. **Honest, formula-level divergence analysis.** Divergence 1 quantifies the AU approximation; Divergence 8 explains why multi-start composition does not change KKT points. The register's structure (code / doc / explanation / impact / recommendation) is exemplary even though its coverage is incomplete.
6. **ADR-style decision log with statuses.** Context/gap/decision/rationale/alternatives/impact/status is the right schema; the failure is execution, not design.
7. **Pre-registered decision matrix A–E**, implemented in code. This is rare and should survive the redesign verbatim.
8. **DVT↔ISD mathematical agreement** on the five consequential identities: D-factor, scalar σ², median-based dual rescaling, principal-basis entropy gradient, validation ELBO excluding γ and λ_co. The theory's math is sound; do not rewrite it.
9. **Unit-aware risk aversion.** The `lambda_risk=252` annualization is documented at the config level (config.py:519–524); this is a correct resolution of an ambiguity the ISD left open.
10. **INV-012: identical constraints for the strategy and all six benchmarks.** This is the precondition for any valid comparison and must not be relaxed.

## Verdict

As advocate, I find the normative core of U17 genuinely strong: the conventions and invariants are precise, mathematically correct where I could check them (D-factor equivalence, scalar σ², median winsorization, principal-basis entropy and its gradient, validation ELBO), enforced in production code, and traceable into a large test suite that cites the same IDs. The divergence and decision registers are well-designed and technically honest within their coverage. What fails is not the theory but the **chain of custody of the theory**: the repository no longer contains one specification. It contains v4.1 (DVT/ISD), a v4.2 implemented in code (market intercept, PC1 exclusion, spiked/EWMA Σ_z, WLS, two-layer entropy, D/2-scaled co-movement, per-factor variance targeting), and a set of justification memos that individually defend pieces of v4.2 without ever becoming normative. The divergence register omits the largest deviations, the decisions log denies that divergences exist, and the cross-reference report is stale. The mathematical spine deserves to be kept almost unchanged; the documentation architecture deserves to be replaced by one machine-checked source, not augmented with another document. Soundness of the unit's *design and mathematics* is high; soundness of its *currency and completeness* is moderate; the average is 7.

Score: 7/10
