## Five questions

**1. Purpose and original intent.** The stated intent is falsification, not a leaderboard: "la complexité du VAE n'est justifiée que si elle produit un bénéfice OOS mesurable et statistiquement significatif par rapport à des alternatives plus simples, sur les mêmes données, avec les mêmes contraintes, évaluées par les mêmes métriques" (`docs/Benchmark_latent_risk_factor.md:5`), with the operational rule "Toute divergence invalide la comparaison" (`:11`). Each rung is meant to neutralize exactly one layer (`:146`, `:158` in §7), and the whole unit exists to adjudicate a five-way decision (`:288–303`). So the unit's purpose is to be the *kill switch* for the VAE — the most epistemically important unit in the project.

**2. State of the art.** The current design answers "which portfolio has the best realized Sharpe/vol?" The modern answer to "is my factor risk model better?" is different in kind:
- Separate **risk-forecast quality** from **portfolio construction**. Score every Σ̂ with a proper scoring rule (QLIKE or MSE on realized variance; Engle–Colacito 2006, Patton 2011) and with the covariance-realized-vs-predicted correlation it already names in §3.3 (`:184–188`) — but apply it to *all* models.
- **Capacity-matched linear baselines.** Gu–Kelly–Xiu (2020) and Kelly–Pruitt–Su (2019, IPCA) compare nonlinear and linear factor models at matched capacity/regularization; Bai–Ng (2002) gives a *number* of factors, not a substitute for a capacity sweep.
- **Matched objectives.** If the claim is "factor-space entropy beats asset-space diversification", the factorial control is (risk model) × (objective), with both cells populated (Roncalli 2013 Ch. 7; Meucci 2009; Clarke–de Silva–Thorley 2013 already cited at `:308`).
- **Estimation-error accounting.** DeMiguel–Garlappi–Uppal (2009), Kan–Zhou (2007): the 1/N result is a statement about estimation error under a *specific* universe and window; it is not portable to a different universe.
- **Multiple-testing.** Harvey–Liu–Zhu (2016) style discipline if the benchmark set grows; Holm is already implemented (`reporting.py:99–108`).

A SOTA U13 would therefore be: one shared simulator, one shared universe snapshot, Σ-forecast scoring for all models, a matched-capacity linear and a matched-capacity nonlinear competitor, and equivalence tests (TOST) for the "≈" claims.

**3. What prevents it.** Evidenced blockers, not hypotheses: (a) benchmarks and VAE run through *different simulators* with different return accounting (`base.py:171–175` vs `oos_rebalancing.py:640–699`); (b) the linear competitor is not capacity-matched (`:146`); (c) the primary metric does not exist for any benchmark (`metrics.py:680–688`, `reporting.py:46–49`, blank column in `strategy_comparison.csv`); (d) the decision rule is a default branch (`selection.py:97–142`, `results/diagnostic/report.txt`); (e) one benchmark silently degenerated to 1/N (`erc_fold_metrics.csv` ≡ `equal_weight_fold_metrics.csv`).

**4. Real vs self-imposed constraints.**
*Real:* n≈478–788 with T≈2 500–7 500 per fold means n/T≈0.1–0.3, so sample eigenvalues of PCA are Marchenko–Pastur-inflated; the long-only 3–5 % cap genuinely compresses weight dispersion; CRSP is unavailable; SCA + SVD per fold is the compute budget.
*Self-imposed:* the six-rung ladder instead of a factorial design; one IC₂-selected k instead of a k-sweep; the "tune the VAE's penalties once and freeze them for everyone" rule (`:48`), which makes every benchmark a stranger to its own objective; a 6-month single-shot hold for benchmarks; 1/N as the failure fallback; using the VAE's latent-space entropy as a cross-model "primary" metric; and the default-to-C decision rule.

**5. What should be removed, merged or moved.**
- **Remove** the cross-model `H_norm_oos` claim (keep it as a diagnostic, not a decision metric); the `np.ones(n)/n` fallbacks; `check_deployment_criteria` as a second decision path; `diversification_ratio` computed with each model's own Σ; the unconstrained S&P 500 from the six-way decision (move it to a context row).
- **Merge** the three benchmark harnesses (`run_benchmarks.py`, `_run_benchmark_fold`, `simulate_benchmark_oos_rebalancing`) into the single VAE simulator; merge min-var and ERC into one "direct-covariance" family sharing Σ_LW and reporting both objectives; merge PCA and PCA+vol into one linear-factor family with a feature toggle.
- **Move** risk-forecast comparison *before* portfolio comparison (same Σ̂, scored, then used); universe construction out of the fold loop into one point-in-time module; the entropy objective out of individual benchmarks into a shared portfolio-construction layer so it can be applied to *every* risk model (including LW and 1/N), which is the only way to identify whether gains come from factors or from entropy.

## Root-cause hypotheses

**RC1 — The benchmark set is a narrative ladder, not a factorial experiment.** Six rungs were written to *tell a story* ("each neutralizes one layer", doc `:158`), so no benchmark is a matched control for any single factor: PCA differs from the VAE in capacity, features, prior and optimizer simultaneously (CRI-05), and no cell exists with (VAE Σ, ERC objective) or (LW Σ, entropy objective). This one design choice generates CRI-05, MAJ-09, and the impossibility of attributing any Δ. *Structural alternatives:* (a) a 2×2 experiment — risk model {LW, PCA-k, VAE} × objective {min-variance, entropy-RP} — with the same simulator and the same Σ for both objectives; (b) report PCA as a **capacity curve** k ∈ {5,10,20,40,80} instead of one IC₂ point, so the VAE must beat the *envelope*; (c) an "extractor swap" test: hold the objective and optimizer fixed, change only returns→B, and measure Δ — this is the only clean statement of "nonlinearity helps". Trade-off: many more portfolio solves, and the single-number benchmark table (which is what makes the doc readable) disappears.

**RC2 — Two harnesses, one strategy: model comparison is implemented at the wrong layer.** The VAE runs through a full daily simulator with drift, costs, delisting and quarterly rebalancing; the benchmarks run through `evaluate()` on a constant-mix portfolio with zero delisting and no costs (CRI-03). This exists because the benchmark interface (`fit`/`optimize`/`evaluate`) was specced as a lightweight abstraction (ISD `2001–2026`) while the VAE needed a stateful simulation. Consequences: MAJ-14, MIN-15, MIN-20, and part of MAJ-06. *Alternatives:* (a) collapse to one simulator and a `fit/optimize` adapter — every model, including 1/N, goes through the same return accounting; (b) register benchmarks in the same walk-forward driver as the VAE and delete `run_benchmarks.py`; (c) add an "identity test": run the VAE's own B, Σ_z, D through the benchmark path and require byte-identical metrics. That single test would have caught CRI-03 on day one. Trade-off: the benchmark classes must be refactored and lose their standalone CLI; runs get slower.

**RC3 — Silent degradation is the house style, and the decision rule was built to consume it.** `try/except → 1/N` appears in both harnesses (MAJ-12), solver failure has no provenance, and the scenario logic has a default branch (CRI-02). The system is therefore *structurally unable to report "this comparison is invalid"*, which is the only honest output when a benchmark never ran. Consequences: CRI-01, CRI-02, MIN-18. *Alternatives:* (a) fail-closed — a model that did not solve is *missing*, and any fold with a missing cell is dropped from the paired test and counted in the report; (b) make solver status and the model's defining property (ERC RC dispersion, PCA explained variance) first-class output columns, checked with an assertion like `assert_weights_sum_to_one`; (c) replace the scenario table with pre-registered equivalence tests (TOST) so "≈" is measured rather than defaulted. Trade-off: more failing runs surfaced, fewer "completed" reports.

**RC4 — Each model is scored on its own native, self-referential metric.** H_norm lives in the VAE's latent basis and is normalized by its own K (MAJ-07); `diversification_ratio` is computed with the model's own Σ (MAJ-08 / `metrics.py:693–700`); risk-forecast accuracy is measured only for the VAE. The comparison therefore degrades to vol/Sharpe — the two dimensions the strategy was explicitly *not* designed to win (doc `:170–179`). *Alternatives:* (a) one model-free diversification measure computed from the realized OOS covariance for every model (e.g. ex-post ENB, or effective number of independent bets from realized correlations); (b) a three-column verdict per model — forecast quality, diversification, net-of-cost performance — so a model can win on the objective it was built for without hiding its costs; (c) score every Σ̂ with QLIKE/MSE on realized variance (Patton 2011), which is the decision-relevant quantity for a risk model and is comparable across all five models. Trade-off: the "factor entropy" selling point stops being the headline, and the VAE can no longer win on a metric defined in its own coordinates.

**RC5 — Universe and delisting are treated as plumbing rather than as part of the estimand.** The comparison population is a NaN-thresholded Tiingo set (MAJ-06) with zero delisting returns on the benchmark side (CRI-03) and a 50 %-NaN rule that removes dead names from later folds. Because the bias is shared, it is invisible in relative comparisons; because it is large (35.3 % missing per `health_checks.csv`), it dominates absolute numbers, and it changes *which model looks diversified* (many tiny names vs few liquid ones). *Alternatives:* (a) implement the documented point-in-time screens once, and treat "universe" as an experimental factor with two levels (Tiingo-raw vs doc-compliant); (b) run the head-to-head on the intersection of all models' feasible universes, with the full-universe run reported separately; (c) add a "1/N on the doc-compliant universe" row so universe effects can be subtracted from optimization effects. Trade-off: requires data work outside this unit, and the sample size falls.

## Verdict

**Steelman.** The design is better than most academic benchmark suites: it is pre-registered in prose, it includes a 1/N control for exactly the DeMiguel reason, it has an ERC control that isolates factor-space from asset-space diversification, its PCA control is *intended* to be the decisive one, and the statistical layer (Wilcoxon + bootstrap + Holm) is actually implemented rather than asserted. The intent — a kill switch, not a leaderboard — is the right intent, and the doc anticipates the main failure mode (over-tuning benchmarks, `:48`).

**Rebuttal.** None of that survives contact with the code. The kill switch has a default position that kills the VAE (`selection.py:97–142` → "Scenario C" with zero tests). One of the six controls never ran and silently became 1/N (`erc_fold_metrics.csv` ≡ `equal_weight_fold_metrics.csv`). The decisive control is not a control: it is given a different optimizer configuration, a different factor count, and a different feature set, and the doc itself lists those differences as the thing being measured (`:146`). The two sides are scored by different simulators, with different rebalancing, different costs and different delisting treatment (`base.py:171–175` vs `oos_rebalancing.py:640–699`). The primary metric exists only for the VAE and is normalized by a hyperparameter. The only full-scale result has n=1 and reports all tests as skipped, yet still prints a scenario and a recommendation. The unit is therefore not currently capable of falsifying anything; the correct output of the existing machinery is "inconclusive", and the machinery is constructed so that it cannot say that. The fix is not more benchmarks — it is one simulator, one universe, one factorial design, and a decision rule that returns "no evidence" when there is none.

Score: 2/10
